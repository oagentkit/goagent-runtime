title: ADR-0006 · 容器后端是参考实现

---


| 项 | 内容 |
|---|---|
| **状态** | 已采纳（Accepted） |
| **日期** | 2026-11-22（自 kernel v0.68.0 迁入本仓，v0.3.0） |
| **背景** | kernel 的 `backend` 只给契约与判据。把某个容器引擎的接法写进仓里，等于把**一种部署形态焊进依赖面**——于是「依赖面窄」这条纪律在容器这条线上被开口子，且每次换引擎都要再动一次依赖面。 |
| **决策** | `containerbackend` 是**参考实现**：Docker（`docker.go`）与 Kubernetes Job（`k8sjob.go`）两份，都走 **stdlib `net/http`** 直接对接引擎 API——不引 Docker 客户端库，也不引 client-go。分工与存储参考实现同构：**宿主抄它，不 import 它**。 |
| **后果** | ① 部署形态不进入本仓依赖面；② 宿主拿到的不是「一个必须跟随本仓版本的包」，而是一份可以照抄的接法；③ 生命周期定为 Experimental（沿用 kernel 侧 `api-lifecycle` 的定级）——参考实现随契约与真实引擎形态演进，不构成任何兼容承诺。 |
| **依据** | 仓内 `containerbackend` 包文档注释；kernel 的 `backend` 契约包与 `api-lifecycle.yaml` 定级规则。 |

&gt; **一句话结论**：容器后端是参考实现——宿主抄它不 import 它，部署形态不焊进依赖面。

---

## 两种接法，零第三方依赖

| 引擎 | 对接方式 | 第三方依赖 |
|---|---|---|
| Docker | Docker Engine HTTP API（unix socket 或 TCP） | 无（stdlib `net/http`） |
| Kubernetes Job | kube-apiserver HTTP API（in-cluster token / CA） | 无（stdlib `net/http`） |

不引 client-go 的代价是手写 apiserver 调用；换来的是依赖面不因部署形态变宽——
与「内核依赖面窄」同一条纪律的另一种落地方式。

## 「宿主抄它，不 import 它」是什么意思

它不是客套话，是**分工**：

- 本仓提供的是「怎么接」的参考（映射表、配置面、生命周期），不是「接好了给你用」的依赖；
- 宿主需要容器后端时，照着这份实现接到自己的后端契约上；
- 因此本仓可以为它改实现而不算破坏性变更——它本来就不在别人的依赖图里。

这与存储参考实现（`pgstore` / `sqliteadapter`）是同一种分工：
它们跑 kernel 的共享契约套件以证明判据一致，但宿主要的是**用法**，不是 import。

## 生命周期

Experimental——参考实现随契约与真实引擎形态演进，不构成任何兼容承诺。
定级理由与分级规则见 kernel 的 `api-lifecycle.yaml` 与 `docs/api-compat.md`。
