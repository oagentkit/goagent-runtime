goagent-runtime 是 goagent-kernel 的装配层：内核负责「失败后到底允许做什么」的确定性判据，本层负责把它们接成 「模型 ↔ 工具 ↔ 存储」的完整回路。进程崩溃后接着跑而不是重做——这不是口号，是每条判据都有测试钉着的契约。

四层各归其位

边界纪律是本项目的骨架：每一层只认识自己那一半，判据单源、依赖单向。

宿主产品
只写领域：系统提示、工具实现、模型供应商适配。不读内核几十个包。
goagent-runtime
本层：回合循环、工具施加管线、存储装配、事件观测的接线与默认口径；SQLite / PG 参考实现与编排演示住在这里。
goagent-kernel
判据本体：副作用闸、检查点、回合守卫、任务板、租约会话、控制面——零数据库驱动的纯契约仓。
oagentkit / oekit
上游原语：沙箱档位、并发安全、结构化错误。

三种部署形态

用户给出的只有领域输入；存储、事件、判据装配全是模板的事。

NewEmbedded可用

内存存储、零外部依赖。单进程、测试、内嵌场景。判据与持久化形态同构，日后升级 standalone 只换一行。

用户提供：模型客户端 + 工具列表

NewStandalone可用

SQLite（WAL 单文件）持久化。进程重启后同一 sessionID 从快照恢复，历史一字不丢。

用户提供：模型客户端 + 工具列表 + SQLite 路径

cluster下一步

PostgreSQL + worker 池的多副本形态。前置已清：kernel 两项 P0（权威介入原子审计、租约持续故障失格）已在 v0.64.1 / v0.64.3 修复；PG 存储与 worker 契约已在本仓就位。

将提供：模型客户端 + 工具列表 + PG DSN + worker 配置
定位边界（如实声明）：本仓提供装配层与参考实现，不保证所有机制已组成可直接部署的高可用 Runtime； 实际能力以各模板的集成测试证据为准。cluster 模板在真实多副本故障注入验证通过前不发布——把未验证的机制固化成默认路径，比没有模板更糟。

五分钟接入

任何模型 SDK 包一层 chat.Model 适配即可接入；本仓不 import 任何具体供应商。

// go get github.com/yi-nology/goagent-runtime@latest

rt, err := runtime.NewStandalone(runtime.Config{
    Model: myModel, // 实现 chat.Model：一个 Chat 方法
    Tools: []pipeline.Tool{{
        Name: "查库存",
        Handler: func(ctx context.Context, args []byte) (string, error) {
            // …你的领域逻辑…
        },
    }},
}, "/var/lib/myagent/agent.db")

res, err := rt.Run(ctx, "session-1", "帮我查一下 A 仓库存")
// res.Status / res.Final / res.Rounds / res.ToolCalls / res.Uncertain

恢复语义：进程死了，接着跑，不重放

这是本层的核心命题。每个承诺下面都有一条会红的测试。

进程 1

执行到一半

工具已施加、结果已回填、快照已落库——然后进程在下一轮模型调用前死亡。

进程 2

同一 sessionID 再 Run

从 checkpoint 读回完整会话历史（系统提示 + 对话 + 工具结果），模型按历史继续。

副作用闸

重放同一调用

模型若重发同一个 toolCallID，闸判 replayed——直接取回既有结果，执行体不会被再次调用。

  • 提交点自洽——回填与提交在同一段顺序代码里，崩溃窗口两端各自完整：恢复出来的历史要么有这一段，要么没有。
  • 不完整历史 fail-closed——assistant 请求了工具但结果缺失＝存储被外部篡改，报错不猜，拒绝静默续跑。
  • 幂等键同源——toolCallID 由编排侧铸造（可注入），assistant 消息里的 ID 与副作用幂等键是同一份；模型不给 ID 时由 loop 补发。
  • 结果未知禁止盲重试——远端是否生效由远端说了算：OutcomeUncertain 显式上抛为 res.Uncertain，该键必须先对账裁决。
  • 预算在调用前判定——roundguard 的额度检查在模型调用之前，用尽按策略强制收尾（ForceFinal 给最后一次终答机会）或直接停止。
  • 施加次数恒为 1——端到端用例断言：中断恢复后计数器不增。SQLite 形态下跨进程同样成立（库文件即真相）。

判据不另写一套

存储语义全部来自 kernel 契约；本仓只做实现，共享契约套件在真实落库形态上同跑。

判据证据
sideeffect 契约kernel sidetest 共享套件（33 子测试：只做一次 / 令牌单调 / 过期接管 / 执行意图 / 对账占用 / 带凭据裁决……）在内存、SQLite、PostgreSQL 三个实现上同跑

包结构

六个装配面包 + 三个参考实现 + 两个可运行演示。

包职责
chat供应商中立的模型窄接口（唯一模型接缝）与消息类型
pipeline工具施加管线：toolCallID = 副作用幂等键、会话资源互斥、重试安全性显式声明
agentloop可恢复回合循环：预算调用前判定、历史落 checkpoint、事件发射
storage存储装配面：内存判据移植 + SQLite/PG 门面转发
runtime模板装配：NewEmbedded / NewStandalone（+ 选项注入）
observeeventbus → 宿主回调（日志 / 指标 / 审计各写一个 Sink）
sqliteadapter / pgstoreSQLite（WAL）与 PostgreSQL 参考实现，11 面统一门面
containerbackendbackend 契约的 Docker Engine / Kubernetes Job 参考实现（含 NetworkPolicy 声明面判据）
examples/embedded / standalone 演示（中断恢复、跨进程续跑）+ reference-runtime / worker-runtime 接线样板
