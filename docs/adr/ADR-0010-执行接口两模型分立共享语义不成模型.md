# ADR-0010 · 执行接口两模型分立，共享语义不成模型

| 项 | 内容 |
|---|---|
| **状态** | 已采纳（Accepted） |
| **日期** | 2026-11-27（W2 切片 1，#39 边界定型 / #37 问题二） |
| **背景** | README 分层写「Loop / Pipeline / 存储 / 事件 的接线」，但仓内只有 `agentloop` 一个执行模型；`pipeline` 包是工具注册与副作用施加，**不是**定步流水线执行器。演进评审（#37 问题二）点名两个方向的风险：① 若为「统一」把自主决策与定步流程压成一个执行模型，两边都变形——Loop 的本质是模型决定下一步，Pipeline 的本质是依赖图决定下一步，压成一个必然有一方被扭曲成模拟；② 若放任不管，未来可能在本仓长出第二套流程引擎，撞家族已有的 `oekit/workflow`（串行/并行/异步/条件四模式），Multi-Agent 若自造拓扑守卫则撞 `oagentkit/agent/dispatch`（allow 矩阵 + 深度上限）。家族先例 runtime#24 已裁「同形不抽、各自成文」。 |
| **决策** | 两种执行模型**分立**，边界判据是**谁决定下一步**；不强行统一成一种执行模型，但共享同一套基础语义（Run / Step / Checkpoint / Event / Cancellation）。共享的是**语义与读面**，不是控制流抽象：判据仍全部来自 kernel（checkpoint / eventbus / roundguard / sideeffect），本仓不发明第二套。家族组合规则钉死：定步流程力学若立项则**组合 `oekit/workflow`**、Multi-Agent 拓扑守卫**组合 `oagentkit/agent/dispatch`**，本仓不自造流程引擎、不自造拓扑守卫；工具副作用一律走 `pipeline` 幂等闸，不因换了执行模型就绕闸。Pipeline 执行器**若立项**才建，本 ADR 只定边界不承诺建成。 |
| **后果** | ① 统一压力被结构性挡掉：未来有人提议「把 Loop 和 Pipeline 抽成一个 Graph 执行器」时，本 ADR 是拒收依据；② 第二套流程引擎/拓扑守卫不会在本仓出现——组合家族已有件，依赖面增量但判据不增量；③ 共享语义接口是**加法**：不动 `agentloop` 现有语义与判据，新执行模型落地时实现同一组生命周期钩子即可；④ Pipeline 执行器从「 roadmap 承诺」降为「条件立项」——没有消费方之前不写；⑤ README 分层里「Pipeline」一词的含义收窄为工具注册包（现状），执行模型义待立项时再改写。 |
| **依据** | runtime issue #39（本单）、#37 问题二（演进评审）；runtime#24 裁定（同形不抽、各自成文）；`oekit/workflow` 包文档（Pipe/Parallel/Async/Switch 四模式 + ctx 取消传播）；`oagentkit/agent/dispatch` 包文档（EdgeSource allow 矩阵）；AGENTS.md 边界纪律（判据不另写、领域概念全注入）。 |

> **一句话结论**：执行接口两模型分立——Loop 与 Pipeline 不压成一个执行模型，共享的是 Run/Step/Checkpoint/Event/Cancellation 语义与读面；流程力学组合 `oekit/workflow`、拓扑守卫组合 `agent/dispatch`，本仓不自造引擎。

---

## 边界判据：谁决定下一步

| | Loop（`agentloop`） | Pipeline（若立项） |
|---|---|---|
| **下一步谁定** | 模型（自主决策：调工具 → 观察 → 再决策） | 依赖图 / 程序（固定步骤、明确依赖、确定性流程） |
| **控制流** | 非确定（模型输出决定走向） | 确定（步骤与依赖在装配期定死） |
| **已有件** | `agentloop.Loop`（预算守卫 + 检查点 + 事件 + 审批闸 + 账本） | 无（`pipeline` 包是工具注册与副作用施加，非执行器） |
| **失败形态** | 模型失败 / 预算耗尽 / 审批挂起 / 工具 uncertain | 步骤失败 / 依赖不满足 / 取消 |

判据一句话：**控制流的决定权在模型还是在图**。在模型 = Loop，在图 = Pipeline。两者可以组合（Pipeline 的某一步内部跑一个 Loop），但不互相当对方的模拟实现。

## 共享的是语义不是模型

两种执行模型共用同一套基础语义——共享的是**身份、进度、事件、取消的读面与契约**，不是控制流抽象：

| 语义 | 现状落点 | 共享方式 |
|---|---|---|
| **Run**（一次执行的身份与状态） | `Session.Run` / `agentloop.Result`（W1 #38 已落对象面） | 同一入口形态：`Run(ctx, input) → Result`；状态词表归 kernel `contract` |
| **Step**（一步进度） | kernel `checkpoint.Snapshot.Done`（步骤 ID 集合） | 同一快照面登记步骤完成，不各自造进度表 |
| **Checkpoint**（进度与恢复点） | kernel `checkpoint.StoreCAS`（判据单源） | 同一存储契约；新执行模型不得旁路 SaveIfNewer 单调判据 |
| **Event**（过程可观测） | kernel `eventbus`（联合提交 / 水位线判据） | 同一事件面与发射纪律（一轮四事件等既有判据不动） |
| **Cancellation**（取消） | `context.Context` 传播 + ctx 超时归循环 | 同一取消语义：ctx 取消 → 在途步骤收场 → 状态可恢复或终态（W3 #40 钉判据） |

**反例（不共享什么）**：不共享「回合」概念——回合是 Loop 专有（模型调用一次 = 一回合），Pipeline 没有回合；不共享「工具轮」——那是 Loop 的驱动节拍。硬造统一的 Round 抽象就是把一方扭曲成另一方的模拟。

## 家族组合规则（不自造引擎）

1. **定步流程力学** → 组合 `oekit/workflow`（PipeFlow / ParallelFlow / AsyncFlow / SwitchFlow，含 ctx 取消传播与错误豁免规则）。本仓不实现第二套流程编排内核。
2. **Multi-Agent 拓扑守卫** → 组合 `oagentkit/agent/dispatch`（EdgeSource allow 矩阵 + 深度上限 + 自派发拒绝，结构化 DenyError）。本仓不造 allow 矩阵。
3. **工具副作用** → 一律走 `pipeline` 幂等闸（幂等键 / 租约 / uncertain 上抛）。换了执行模型不换闸——绕闸施加是安全缺陷。
4. **进度与事件** → kernel `checkpoint` / `eventbus` 契约面。新执行模型实现契约，不复制判据（AGENTS.md 红线）。

依赖面影响：Pipeline 若立项，主 module 增加 `oekit/workflow` 依赖（矩阵内仓，符合 tier 5 装配层的依赖宇宙）；`agent/dispatch` 同理。判据面不增——组合的是力学，不是判据。

## Pipeline 执行器：若立项的形态（不承诺建成）

本 ADR **不承诺**建造 Pipeline 执行器；立项的前提是有真实消费方（固定步骤 + 明确依赖 + 需要恢复语义的业务流程）。若立项，形态约束：

- 控制流力学组合 `oekit/workflow`，步骤实现同一组生命周期语义（上表）；
- 步骤内的工具调用走 `pipeline` 幂等闸（与 Loop 同一条施加面）；
- 进度落 kernel checkpoint（Step 登记进 `Snapshot.Done`），事件走 kernel eventbus；
- 与 Loop 组合：Pipeline 步骤内可跑 Loop（图的节点是自主决策），Loop内**不**反向嵌 Pipeline（模型决定下一步的循环里塞确定性图 = 语义矛盾）。

## 不做什么（决策的拒收面）

- **不**把 Loop 与 Pipeline 统一成一个执行模型（Graph 执行器 / 万能图）；
- **不**在本仓实现流程编排引擎（组合 `oekit/workflow`）；
- **不**在本仓实现拓扑守卫（组合 `agent/dispatch`）；
- **不**为共享而发明 Round/Step 的统一控制流抽象（共享限于上表五个语义）；
- **不**因执行模型分立而复制任何 kernel 判据。
