# ADR-0001 · 独立成仓

| 项 | 内容 |
|---|---|
| **状态** | 已采纳（Accepted） |
| **日期** | 2026-11-21（初版） |
| **背景** | kernel 的门禁核心之一是「内核包不拖存储驱动」——编排内核的依赖面必须窄到能被多方复用。而 runtime 是**装配层**：它必须直接装配 SQLite / PostgreSQL 驱动与事件面。把这两层放进同一个仓，那条判据当场开口子：内核包的依赖图里会长出 pgx 与 modernc.org/sqlite，于是「内核依赖面窄」这句话不再有判据撑着，只剩散文。 |
| **决策** | 装配层独立成仓（`github.com/oagentkit/goagent-runtime`），依赖方向单向：**runtime → kernel**，kernel 不认识 runtime。存储驱动只出现在 runtime 的叶子包（`pgstore` / `sqliteadapter`），不进装配面（`runtime` / `agentloop` / `storage` / `pipeline` / `chat` / `observe`）。 |
| **后果** | ① kernel 的「内核包不拖存储驱动」判据保持成立，不需要为装配需求开口子；② runtime 可以自由装配驱动与事件面，产品层发版节奏（Beta/RC/1.0）与 kernel 的机制版各发各的；③ 参考实现（存储两件套、容器后端）随迁 runtime 后，kernel 主 module 回到「零数据库驱动」的干净状态。 |
| **依据** | 仓内 README「为什么是独立仓」一节；kernel 侧 `examples/{pgstore,sqliteadapter,containerbackend}` 迁出（kernel v0.67.0 / v0.68.0）。 |

> **一句话结论**：装配层独立成仓——内核的门禁核心是「内核包不拖存储驱动」，把驱动装进内核就是给那条判据开口子。

---

## 同一层里塞两件事会发生什么

「内核 + 装配层放一个仓」在第一周看起来只是少开一个仓库。实际上它改的是**依赖面**：

- 装配层要装 SQLite 与 PostgreSQL 驱动，于是 `storage` 这类包把 pgx / modernc.org/sqlite 拖进依赖图；
- 内核包一旦依赖驱动，kernel 的门禁「内核包不拖存储驱动」就得开口子——而开口子的判据会退化成「大部分时候不拖」；
- 于是 kernel 的依赖面从「窄」变成「看谁先来」，多一个宿主需求就多一条边。

判据一旦从「是 / 否」退化成「基本是」，它就不再是判据，只是散文。

## 发版节奏也是理由

kernel 是机制层：每次改动都要重新论证「这是否仍是机制」。runtime 是产品层：
模板选型、默认口径、接缝便利性都在快速迭代。两种节奏放进同一个 tag 序列里，
结果是机制层被产品层需求拖着改版本号——**依赖别人的仓，被别人拖着自己的版本**，
这在多仓矩阵里是典型的纠缠源。

## 边界长什么样

```
宿主产品        只写领域：系统提示、工具实现、模型供应商适配
goagent-runtime 本层：Loop / Pipeline / 存储 / 事件 的接线与默认口径
goagent-kernel  判据：状态机 / 副作用闸 / 回合守卫 / 检查点
oagentkit/oekit 上游原语
```

这四行就是边界：**本仓往下只认 kernel 的判据面，往上不认任何宿主的概念**。
